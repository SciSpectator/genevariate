# Reproducibility and limitations

## 1. The run manifest

`core/reproducibility.py`

A tool that can be driven by a language model has to be able to say exactly how
a result was produced. `build_manifest` captures the four things needed to
reproduce an analysis into a plain dict that serialises to JSON or renders as
markdown, and it can be attached to any result:

| Captured | Detail |
|---|---|
| Parameters | the resolved arguments of the call, not the ones the user typed |
| Software versions | genevariate, numpy, pandas, scipy, scikit-learn, gseapy, anndata, diptest, decoupler, harmonypy, combat, statsmodels, plus Python and platform |
| Random seeds | the seed each stochastic step was given |
| Data hash | SHA-256 over the input frame's shape, column names and values |

Version probing degrades gracefully. A package that is not installed is recorded
as `not installed` rather than raising, because "this ran without decoupleR" is
itself a fact about the run.

The hash works on DataFrames, arrays, dicts of either, and file paths. Two runs
that report the same hash saw the same input, which is the claim a filename
cannot make.

Every assistant answer carries the same manifest, recording which tool ran with
which resolved arguments, so any assistant result can be reproduced by hand
through the interface.

## 2. Determinism

Deterministic:

- enrichment counts, Fisher tests, Benjamini-Hochberg
- rho, design effect, effective sample size
- DerSimonian-Laird pooling, Cochran's Q, I^2, tau^2
- the k-way log-linear interaction odds ratio
- relaxation attribution in the box model

Seeded and therefore reproducible run to run, but dependent on the seed:

- bootstrap-by-study confidence intervals
- Monte Carlo integration of `p_uniform` in the box model
- cross-fitting fold assignment, which is split on study
- KMeans in the clustering tools, and UMAP where it is installed

Not deterministic across machines:

- anything that depends on BLAS threading order at floating-point precision
- anything downloaded live, because GEO, ARCHS4 and CELLxGENE are updated

Record the manifest. It carries the seed and the data hash, which is what makes
the second category reproducible and what makes the third category detectable.

## 3. Validation

Unit tests check that a function returns a number. They do not check that the
program, driven the way a user drives it, recovers an answer decided before the
analysis ran.

```bash
python3 tools/make_synthetic_platform.py
python3 tools/validate_synthetic.py
```

The generator plants an AND gate, a single-gene marker, a label confined to four
studies and driven by no gene at all, a gene that means nothing, and a label
column that is pure noise. `GROUND_TRUTH.md` states what each tab must report,
and the validator checks 24 claims against it: that the four-study label is
discounted, that BH-FDR kills the noise column, that synergy separates a real
conjunction from a decoy, that calibration does not get worse, and that
relaxation charges the meaningless gene nothing.

The two CSVs load in the GUI, so the numbers on screen can be read against the
same document.

The synthetic platform is a validation device. Nothing generated by it belongs
in a published result.

## 4. Limitations

### The region has to mean the same thing on every platform

This is the one condition the code cannot enforce for you. Technologies are
related at best by an unknown monotone transform, and the only region
definitions invariant to a monotone transform are quantile based. "The top
decile of this gene on this platform" transfers between technologies. "Above 12"
does not. Brushing an absolute range on one platform and the same absolute range
on another produces two regions that are not the same question, and every number
downstream will be answering the wrong one.

### Labels are as good as the extractor that made them

The five fields come from a language model reading free-text GEO metadata. A
value that resolved to a MeSH heading is a stronger claim than a locally minted
identifier, and the interface keeps the difference visible rather than
flattening it. Where a value was only clustered locally, it groups synonymous
spellings and asserts nothing about what the concept is. Treat a local
identifier as a grouping, not as an ontology term.

A `CVCL_` accession under Tissue means the sample is a catalogued cell line
grown in a flask. Whether that belongs in a tissue comparison is a scientific
decision, and the program surfaces it rather than making it.

### Study clumping is corrected, not removed

The design effect widens an interval to reflect how much independent evidence
the samples carry. It cannot manufacture evidence that is not there. A label
confined to four studies has the information of roughly four experiments no
matter how many GSMs it spans, and if that is not enough to answer your
question, the correct reading of a wide interval is that the data does not
answer it.

The correction also depends on `series_id` being present. Where it is absent the
program reports design effect 1 and says the tests assume independence. That is
a statement about the input, not an assurance about the result.

### Single-cell data enters as aggregate profiles

A CELLxGENE query is aggregated to per-donor per-cell-type profiles before it
reaches any analysis. This is deliberate, because treating a cell as a sample
inflates every count by orders of magnitude and none of that is independent
evidence. The consequence is that within-cell-type heterogeneity is not visible
in GeneVariate, and a question about it needs a single-cell tool rather than
this one.

### Missing genes are dropped, never imputed

The shared-gene matrix used for batch integration is complete case. A gene not
measured on every platform is dropped and the count is reported. This can leave
a small shared space when platforms differ a lot in coverage. Filling those
cells would produce a matrix that is dense and wrong, and on log2 data a
fabricated zero is indistinguishable from a measured low value.

### An empty cell means not identified

The k-way interaction odds ratio is undefined when any cell of the 2^k table is
empty, and the program says so. A continuity correction would produce a number,
and the number would be an artefact of the correction rather than a property of
the data.

### Absence of evidence

The conserved-gene list is qualified by a small difference in means, not by a
large p-value. Nothing in the program treats a non-significant result as a
demonstration of equivalence, and neither should a reader of its output.

### Optional dependencies change what is available

decoupleR, diptest, inmoose, harmonypy, gseapy and archs4py are optional. When
one is absent the feature that needs it raises a clear error and nothing else
changes. The manifest records which were installed, so a result can be told
apart from a result produced with a different set.

### Network state

GEO, ARCHS4 and CELLxGENE are living resources. A platform downloaded today may
have more samples than the same platform downloaded last year. The data hash in
the manifest is what detects this. Cache the downloaded frame if you need a
result to be re-derivable later.

## 5. Privacy

The program is local first. It reads GEO, ARCHS4 and CELLxGENE over the network
and sends nothing anywhere else. The label extractor and the assistant talk to
an OpenAI-compatible endpoint that you configure, and to nothing you did not
configure. No model weights, no API keys and no `.env` file are in this
repository.

If you point the assistant at a hosted endpoint, the text of your prompts and
the computed numbers included in them go to that endpoint. Governance of your
own inputs and of any endpoint you choose remains yours.
